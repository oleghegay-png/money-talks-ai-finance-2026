I have a project idea for Saturday that I think is worth pursuing: an AI Portfolio Risk Gate.

The concept is to build an independent risk-control layer for AI-generated portfolio proposals.

The workflow would be:
1. An AI agent receives a fictional investment mandate and proposes a portfolio.
2. A deterministic Python validator checks the proposal against predefined constraints.
3. If any constraints are violated, the Risk Gate blocks the proposal and identifies the exact violations.
4. The AI revises its proposal, and the validator checks it again.
5. PRISM captures the entire process, including the initial failure and successful correction.

I think this could make a strong Trust & Risk demo because we can show a real failure, an independent control detecting it, and a successful correction.

The goal isn't to build another commercial portfolio optimizer, but to create a technically solid hackathon project and gain practical experience with AI agents and PRISM.

We can use synthetic data and generic constraints, keeping the scope narrow enough to build a complete working demo in six hours.

# Why This Exercise Matters for the Hackathon

## The Real Problem (Why It's Important)

In finance, there's a basic rule: the person who creates an invoice cannot be the same person who approves it for payment. This is called Segregation of Duties (SoD).

Why does this matter? Because when the same person does both, they can steal money. Banks get fined millions of dollars by regulators (SEC, Basel III) when they don't catch these violations.

Today, compliance teams spend thousands of hours manually reviewing logs to find these violations. By the time they find them, the fraud already happened.

# 📋 How the Financial Shenanigans Detector Develops (Step by Step)

## 🎯 The Big Picture (in 1 sentence)

The code calculates a simple formula from real numbers. The LLM reads the CEO's optimistic report and proposes a nice story. The code compares the story with the math. If they don't match, the code blocks the story and shows the evidence.

## 🧮 Step 2: The Code Calculates the Truth

The code runs a simple formula (from Schilit's book, Part Three — Cash Flow Shenanigans):

accruals_ratio = (net_income - operating_cash_flow) / total_assets

Results:

Q1-2024: (150000 - 140000) / 1000000 = 0.10  ✅ normal
Q2-2024: (160000 - 145000) / 1050000 = 0.14  ✅ normal
Q3-2024: (170000 - 150000) / 1100000 = 0.18  ⚠️ getting high
Q4-2024: (250000 - 120000) / 1150000 = 0.31  🚨 SHENANIGAN
Q1-2025: (280000 - 110000) / 1200000 = 0.35  🚨 SHENANIGAN
Q2-2025: (310000 - 100000) / 1250000 = 0.38  🚨 SHENANIGAN

The rule: If the ratio is above 0.25 for 3 quarters in a row, it's a confirmed manipulation pattern.

if ratio > 0.25 for 3 consecutive quarters:
    flag = "CONFIRMED_SHENANIGAN"

The code decides: 
🚨 ALERT — Acme Corp is manipulating earnings.

---

## 🤖 Step 3: The LLM Reads the CEO's Story

The LLM receives the CEO's text and proposes a narrative:

> LLM says: *"Acme Corp shows healthy growth. The revenue increase is justified by market expansion. Recommendation: POSITIVE outlook."*

Notice: the LLM never sees the numbers. It only reads the text. This is the trap.

---

## 🛡️ Step 4: The Guardrail Blocks the LLM

The guardrail is a simple Python function. It compares:

- What the LLM said: *"healthy growth, positive outlook"*
- What the code calculated: *ratio = 0.38, 3 quarters of manipulation*

def validate(llm_narrative, code_result):
    if code_result == "CONFIRMED_SHENANIGAN":
        if "healthy" in llm_narrative or "positive" in llm_narrative:
            return BLOCK
    return ACCEPT

Result: 🚫 BLOCKED

The code produces this trace:
